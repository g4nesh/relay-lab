# Action-policy interface

The environment runs at **10 Hz**. A policy returns one world-frame Cartesian
translation and a gripper command per robot per tick:

```python
Action(delta=(dx, dy, dz), gripper=0)
```

Units are metres; the maximum translation norm is `0.035`. Gripper values are
`-1` (close/attempt grasp), `0` (keep), and `1` (open/release). The simulator clamps
motion to each robot's workspace and rejects non-finite values. The HTTP adapter
rejects oversized actions instead of silently changing model outputs.

The action controls a simplified Cartesian gripper, not a real robot's joints.
A checkpoint trained for a different embodiment cannot be connected unchanged.

## HTTP request

`HttpVLAPolicy` POSTs JSON to the user-configured endpoint with these fields:

| Field | Meaning |
| --- | --- |
| `schema` | `relay-lab.action.v1` |
| `session_id` | Unique per policy instance; regenerated by `reset()` |
| `agent_id` | `picker` or `packer` |
| `control_dt` | `0.1` simulated seconds |
| `action_bounds` | Maximum translation norm and permitted gripper values |
| `instruction` | Local task instruction plus bounded execution feedback |
| `execution_feedback` | Observed action digest and delivered peer reports; empty when disabled |
| `replan` | Discard any cached action chunk when true; it reflects new critical evidence |
| `instruction_metadata` | `kind`, `object_id`, `target_id` from the orchestrator |
| `rgb_png_base64` | Base64 PNG of this robot's masked RGB view |
| `observation` | Local structured observation, described below |

The local observation includes `tick`, `ee_position`, `holding`, `objects`,
`targets`, `packed`, and `order`. Only the packer receives the private order and
packed-slot identities. The picker gets `order: null` and an empty `packed` list.
The local object positions are simulator ground truth: using them is a privileged
state baseline, not vision-only control. A vision-based adapter should use RGB,
the language instruction, and the allowed proprioception, and should document
any extra state it consumes.

The HTTP service must key its history/action-chunk cache by `session_id`. Do not
combine the two agents' contexts, even if they share model weights and a URL.
These IDs are context keys, not authentication credentials. The supplied policy
uses a 10-second request timeout and reports endpoint failures; it never
silently switches to the scripted controller. HTTP policies require RGB rendering
even when `--no-video` skips recording the spectator video.

## HTTP response

```json
{
  "action": {
    "delta": [0.015, 0.0, -0.01],
    "gripper": 0
  }
}
```

Return exactly three finite numeric deltas and a permitted integer gripper
command. The HTTP path requires a separately running model service. That service
must handle image formatting, input normalization, language encoding, output
denormalization, embodiment mapping, and action chunk scheduling. The built-in
local SmolVLA adapter uses the optional `vla` dependency extra and does not need
an HTTP service; see [model selection](model-selection.md).

## Replace one boundary at a time

For a local Python model, implement the `ActionPolicy` protocol in `policies.py`
and instantiate one policy per robot in `runner.py`. Keep the model-loading and
inference code out of `environment.py`.

For a learned task planner, preserve the existing
`decide(observation, inbox, execution_events) -> Decision` shape. It produces an `Instruction` for
its own action policy and an optional message to its peer. It must receive only
that robot's local view and inbox. `env.state()` and the overview camera are
reserved for evaluation and recording.

`FeedbackOrchestrator` composes that planner with a `FeedbackCoordinator`. Before
each decision it obtains the robot's private context. After execution it sends
the action, before/after observations, and verified instruction events to
`digest()`. The returned text enters the next prediction through
`Instruction.model_prompt`; it never establishes task success by itself.

The active central mediator uses a local Qwen LLM. It reads both robots' verified
reports and chooses bounded semantic subgoals. A deterministic local judge
interprets actual simulator changes; SpacetimeDB commits each plan, action and
report before allowing the next phase. Fetch is archived outside the runtime.
The Relay VLA policy consumes RGB, proprioception and the selected instruction
text. Feedback affects it through mediator-selected instructions and explicit
replanning; it does not pretend to understand unrestricted feedback prose.
